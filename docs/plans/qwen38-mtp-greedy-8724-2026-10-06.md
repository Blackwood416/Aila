日期 2026-10-06。当前 A770 驱动经 CIM 和各次运行 metadata 确认为 **32.0.101.8724**，oneAPI 2026.1。之前 9033 的报告保留原含义；没有将跨驱动、跨二进制的差异归因于代码优化。

**保留 GPU greedy：同二进制完整 128-token 循环 19.358 → 19.885 tok/s，+2.72%，节省 175.285 ms。** 剔除首循环为 20.415 tok/s；完整循环仍为 6436.985 ms，距 20 tok/s 的 6400 ms 预算还差 36.985 ms。尚不能声称完整口径 20+ 或生产无损 MTP 已达成。

原 CLI 1833-token prompt，128 outputs；CPU18 A64 mapped cold、冻结 hotset、T2 CPU async、state-only replay、decode attention、projection reuse=3、decode prepare=1、draft hidden reuse=1。均为快速单次筛选，未展开全套测试。

shared FFN 的 gate_up[1280,2560] 与 down[2560,640] 双 token 权重复用仅 +0.176%，节省 11.359 ms，已撤回模式 4。局部逐位检查通过不代表性能收益。原模式 1/2/3 保留。

## GPU greedy 实现与开销

实现暂放在 tests/models/Qwen4ExpGreedyProbe.hpp，由真实 LIVE 探针调用，尚未接入生产 scheduler/sampling：

- 第一阶段 64 个 WG、每 WG 256 work-items；第二阶段一个 64-work-item WG，SG16。
- scratch 和结果在循环前分配，单次选择从回传 248320 个 BF16 logits 改为回传 16 字节结果。
- 比较值后比较最低 token ID，保留原 greedy tie 规则。
- 对整行 BF16 原始 exponent 位检查 NaN/Inf，避免 fast-math 优化掉浮点 finite guard；发现异常仍拒绝结果。
- 没有改 logits、权重精度或验证/恢复流程。GPU 选择暂不与 margin/shadow 诊断同时启用。

同二进制暖完整 T2 窗口的均值：

| 区间 | CPU 选择 ms | GPU 选择 ms |
|---|---:|---:|
| draft | 8.3870 | 7.6294 |
| verify | 79.2756 | 77.6162 |
| 验证 CPU logits 扫描，两行合计 | 1.4050 | 0 |
| 草稿 CPU logits 扫描 | 0.7020 | 0 |
| 验证选择的回传/等待区间 | 3.8196 | 3.7646 |
| 草稿选择的回传/等待区间 | 3.9197 | 3.8922 |

后两行包含等待此前排入队列的 GPU 计算；GPU 模式也包含归约，不能把整个区间当成纯 memcpy 或可全部消除的开销。MtpSelectProfile 只在原同步点计时，不像 stages 一样额外逐层 synchronize。

聚焦测试 AilaQwen4ExpKernelTests --mtp-greedy-only 覆盖 vocab=248320 的随机值、极负有限值、尾部最大值、跨 WG ties、正负零、NaN、正负 Inf、canary 和 USM teardown。测试通过。实际 128-token GPU/CPU 选择结果也完全相同。

## 数值定位：head 与 router

8724 上 T2/T4 仍在 output index 123–127 与 T1 不同，不能把之前的分歧归因于 9033，也没有改变最低 ID tie 规则。

新增 shadow 保存实际 consumer 使用的 router 输入，并使用实际最终 mixer 输入隔离 head；没有开启会强制 pending_mlp.Materialize() 的全局 dump 或 stages。计时被诊断污染，不用于速度结论。

在 pos=1954、count=2：

- **从 T1 历史进入**：B2 row 1 的 logits[1118]/[1870] 为 19.75/19.625；连续 B1 为 19.625/19.75，top1 分别 1118/1870。这个当前窗口本身也可以产生分歧，不能只归因于此前累积漂移。
- **从 T2 历史进入**：两条分支都给出 19.625/19.625，按原规则选择 1118，复现了之前的观察。
- **相同最终输入的 head-only 对照**：两种历史下、每种两行的全部 head logits，B2 对两个 B1 都逐位一致。该窗口差异来自 head 之前。
- **相同 router 输入的对照**：T1/T2 两种入口下，48 层各 49152 个 scores 中分别 5/1 个不同，max_abs=0.03125；top-k IDs 均无变化，weights 最大差 2.98e-8 / 1.49e-8。这没有证明所有 router 数学逐位相同，但本窗口没有因它改变专家选择的证据。

原始记录：tmp/mtp-8724-shadow128.*。不要将 shadow 的吞吐或开启诊断后的局部对齐当成普通 LIVE 已对齐。

补充的 tmp/mtp-8724-gdn-shadow128 使用单行 GDN 参考，从 T1 的同一检查点对比 B2/连续 B1。在这个参考模式的窗口内，两路 row 1 都选择 1870，关键两词分数均为 19.625/19.75，层 0 的 GDN 状态逐位一致；但 row 1 仍有 203810 个 logits 不同（max_abs=0.1875），层 1 的状态也仍不同。该补充使用收尾版本 EXE，不将它与先前 EXE 的数值变化包装成严格单变量归因；本次窗口内的两分支比较是同 EXE、同 checkpoint。下一轮可以优先比较首层输出/MLP 与下一层 PLE/HC 的实际输入输出，不能从首层状态相同推断整层已完全对齐，更不能声称长轨迹已经修复。
