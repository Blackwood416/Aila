## 保留实现

src/ops/Qwen4ExpAttentionPair.hpp 是限定形状的实验实现：Hq=24、Hkv=2、D=256、BF16、两个连续 causal queries，长度至少 1024。两个查询共享一次 K vec8 加载、一次 V 加载；各自保持独立点积、softmax 和部分结果，逐行可见长度分别为 start_pos+1 和 start_pos+2。

第一阶段仍按 head/tile 分组，Tile=128、WG128、SG16；第二阶段逐查询/head 合并，保留原 BF16 舍入和 fused sigmoid gate。两个 kernel 使用显式名称。没有改变 KV 布局、权重精度或 GDN 状态。

src/models/Qwen4ExpPrefill.cpp 在 VerifyDecodeAttention=1、VerifyAttentionPair=1、count=2、dense QSA、无 interior snapshot、无 window/sink 且 scratch 足够时使用该路径。其它条件沿用已有路径。partials 复用 buf_.incr_scores 的已预分配 phase 区域：QKV prepare 完成后才写入，Q、gate 和持久 KV 均不位于该区域，in-order queue 维持先后关系。没有增加 steady-state USM 分配。

不保留后台线程或 future。LIVE 在 requestStart 之后同步准备一次 executable kernel bundle，并在双查询提交时复用它；准备耗时包含在 target prompt 与请求总时间中。bundle 由该次 LIVE 的局部 optional 持有，backend 只借用指针；作用域退出先清指针、排空队列，再释放 bundle。开关默认关闭，未接入生产采样/scheduler 的默认配置。

## 数值与结论边界

所有新双查询 LIVE 的 128 个输出都与各自 T1 参考一致；原 attention 对照仍在 output indices 123–127 不同。旧 T2 与新双查询的首次输出差异是 index 123，advance 也不同；target CPU tasks 从 24397 变为 24229。因此 A 的完整生成比较不是严格相同轨迹的算子速度比较。

局部随机测试逐位通过不能推广成全模型所有 attention 输入或 B1/B2 长轨迹均逐位一致。这里尚未证明普遍的无损 MTP，只确认了本 prompt 的 token parity。该数值边界不应被完整 20+ 的速度掩盖。

各次有效 LIVE 的 hotset 首尾都是 7625625710176325289，USM delta=0。没有换提示词、缩短输出、去掉首窗或扩大专家缓存。
