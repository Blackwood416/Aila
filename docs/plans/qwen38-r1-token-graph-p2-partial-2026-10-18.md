Scope: A770 Windows, oneAPI 2026.1, Level Zero 1.28.2, Hyper-V enabled.
Probe: `tmp/q4e-token-graph-probe-20261017/probe_token_graph.cpp`

Receipt: `gpu-real-moe-p2-forced.log`

## 0. Verdict

The graph now captures a real layer-0 GDN front **and** a real masked resident
MoE dispatch:

```text
GDN front + router
  -> route publish to uncached host ring
  -> device resident classify
  -> fixed top-10 masked NF4 gate/up
  -> fixed top-10 masked NF4 down
  -> bounded device wait
  -> mapped-host result copy
  -> graph verification
```

The test route contains five GPU-resident experts and five cold experts. The
`selected[k] < 0` entries exit in the existing resident kernels; no dynamic
launch count is required.

## 2. What is proven

- The adaptive cache's device slot table can produce a dynamic resident mask
  inside a captured graph.
- The graph can index a stable all-slot descriptor table and call the existing
  `moe_resident_gate_up/down` fixed-top-10 kernels.
- A mixed resident/cold mask preserves the original rank positions and the
  graph MoE down output matches the direct resident path bitwise.
- Removing the repeated graph-event status query from every payload poll keeps
  the handshake valid; the dynamic batch is released once after launch.

## 3. What is not proven

This is deliberately not a full decode layer yet:

- CPU classification still uses a forced test route, not the real router route
  for the MoE portion;
- no real `CpuWorker` job or host-arena cold computation;
- no 64-byte rank map plus 16-row CPU packet copied through a mapped-ring kernel;
- no shared-expert add or residual merge;
- no real-route layer-0 comparison, QSA layer, two-layer chain, or 48-layer graph;
- the descriptor table assumes frozen residency (no swap) and is only valid for
  layer 0's nested metadata.

The existing result ring is only 320 bytes of float data. The next probe must
carry a real CPU packet (roughly 50-100 KiB/layer) and must not use
`queue.memcpy` inside the graph.

## 6. P3 capture constraints

The current stack supports a fixed-topology Limited Graph, not mutable kernel
arguments. The P3 shape should therefore be:

- one executable per session and topology, with one graph in flight;
- every tensor/state pointer baked at capture time;
- a 64-byte uncached scalar table for `position`, `cached_len`, GDN/PLE conv
  head and QSA block counts;
- separate graph variants for GDN/full-attention and QSA-active paths;
- host embedding and PLE preparation outside the graph, with a fixed PLE
  staging slot;
- device route ids/weights and selected mask as fixed device buffers;
- CPU packet transport through a mapped-copy kernel, never `queue.memcpy`;
- host session mirrors advanced only after the replay completes.

The current P2 probe satisfies the resident dispatch and packet transport
parts, but not the scalar table, PLE/QSA variants, or real `CpuWorker`.

## 7. Real CPU pipeline integration

The synthetic packet writer has now been replaced by the real existing CPU
pipeline:

```text
device graph publishes x + real router route
  -> host reads route from uncached ring
  -> Qwen4ExpExpertExecutor::RunGraphColdPacket
  -> existing CpuWorker + Qwen4ExpHostArena
  -> real 16-rank CPU packet
  -> graph mapped-copy kernel + ordered merge
```

`RunGraphColdPacket` uses one synchronous worker job, the existing pinned
scratch/output banks and the native host arena. It submits/waits no SYCL copy
and does not mutate adaptive residency. This is a service entry only; the
production scheduler remains unchanged.

The first call pays page/scale warm-up; 1,000 subsequent calls remain bounded.
This is the first real end-to-end single-layer graph CPU handoff, not a full

Resident dispatch remains covered separately by the forced 5-resident /
5-cold test and its packet merge receipt. The current real route happened to
be all-cold for layer 0.

The single-layer graph is not the adoption shape. Direct front median was
538.1 us and the real CPU service was about 346 us; the complete graph replay
was 920 us. A graph boundary per layer therefore provides no standalone win on
this shape. The measured case supports the whole-token graph: its value is
removing the approximately 984-kernel host submission loop across all 48
layers, not wrapping each layer separately.
