# R1-E1: MTP Top-1 agreement gate (supersedes the tensor-bitwise `--mtp-align` gate)

Date: 2026-10-15. HEAD `df1f45a`. Scope: Qwen4Exp MTP decode quality position.
Method: source review + a zero-code log comparator; **no src change, no rebuild,
no GPU run by E1**. Every number below is quoted from an existing log.

## 0. TL;DR

- Gate definition chosen (section 1): **teacher-forced per-step Top-1 agreement**
  = fraction of positions where the batched (width>1) verify forward returns the
  same argmax token as the single-row T1 forward, with both fed the *same* T1
  prefix. Target: >= 0.95 at width 2 for every prompt length.
- Already measured, current build, existing log
  `tmp/q4e-sprint-r1-20261014/mtp-live-w2-g1.log` (30-token prompt):
  **61/63 = 0.9683 at width 4 -> PASS** (mismatches at positions 10, 26).
  The same run's position-wise *stream* agreement is **12/64 = 0.1875** - that
  number is chaos, not quality, and must not be the gate (section 1.2).
- The 121-differing-tensor `--mtp-align` number is a bit-exactness metric; it is
  neutral to the G1 change (121 with and without the gate) and is not a quality
  statement. It is superseded by this metric (section 2).
- Cost of the remaining work: one probe run per prompt length, ~5 min (short
  512) and ~8-10 min (long 1833) `[est]`, plus a CPU-only comparator run. The
  run that decides the gate is the paste block in section 5.

## 1. Metric definitions (pick once, never re-interpret)

Three quantities are computable from lines the probe already prints. They are
different, and only one of them is a quality gate.

### 1.1 C - draft acceptance input (not a gate)

Along the T1 trajectory, anchor at position `p` feeds `tokens[p+1]` to the draft
and compares the three chained draft argmaxes with `tokens[p+2]`,
`tokens[p+3]`, `tokens[p+4]` (`tests/models/Qwen4ExpMtpAcceptance.hpp`,
`[MTP PASS]` / `draft_tokens` / `accepted_prefix`). Yields
`p1 = P(accept first draft)`, `q2 = P(2nd | 1st)`, `q3 = P(3rd | 2nd)`.
This is the speed input (`tokens/step = 1 + p1 + p1*q2 + ...`), not a quality
gate: a rejected draft token is discarded and replaced by the target argmax, so
large p1 with a broken target path is still bad, and small p1 with an exact
target path is still exact.

### 1.2 A - committed-stream agreement (position-wise; chaos-amplified)

`rate_A = |{i < min(len(mtp_stream), len(t1_stream)) : mtp[i] == t1[i]}| / n`.

Why it cannot be the gate: both streams are self-conditioned. One argmax flip at
position k changes the prefix for every later position, so the streams lose
lock and never re-converge. Measured in the current log: 11 consecutive matches,
first divergence at 11, then only 1 match in the remaining 52 positions
(`post_divergence_rate = 0.0192`). The 11-token prefix is consistent with the
single teacher-forced flip at position 10 seen in the same run. So `rate_A`
measures "time to first flip + chaos", which is why it is reported together with
`first_divergence` and the post-divergence rate, and never alone.

Useful properties of A: it is the *end-to-end* statement (what the user would
see), and at width 1 it must be exactly 1.0000 (the width-1 arm is the T1 path);
observed 128/128 and 64/64 in old logs (section 4). It is the hardest arm to
pass and is reported as a diagnostic band, not as the 95% gate.

### 1.3 B - teacher-forced per-step Top-1 agreement (THE gate)

For every position `k` of the T1 trajectory, feed the *T1* token stream in
batches of `W` rows (`Access::VerifyRows(ids + t, W)`) and compare the argmax of
row `r` (= the token the batched path predicts after consuming `tokens[k]`) with
`tokens[k+1]`:

```
rate_B(W) = |{k : argmax_row_k == t1_stream[k+1]}| / K
```

The prefix is identical for both paths, so no chaos enters: this is exactly the
per-step "Top-1 token agreement" the gate asks for. It is also the production
quantity, because the production width-2 window commits target argmaxes only
(`src/models/Qwen4ExpMtpRuntime.cpp:115`: accept iff target row-0 argmax ==
draft; the committed token is that argmax). It requires
`AILA_Q4E_MTP_VERIFY_PASSES >= 1` (default 3) and, to sweep widths, the existing
`AILA_Q4E_MTP_WINDOW_SWEEP=1`, which runs widths 1, 2, 3, 4 in one process.

Gate: `rate_B(2) >= 0.95` for every prompt length; `rate_B(1) = 1.0000` is the
built-in self-check (width 1 is the same code path that generated the reference,
so any value below 1.0000 means the comparison or the run is broken, not that
quality regressed).

## 2. Why `--mtp-align` / StateDigest is the wrong tool here

- `src/models/Qwen4ExpStateDigest.hpp` hashes raw bytes (FNV-1a over 8-byte
  words) of session state; `tests/models/Qwen4ExpMtpAlign.hpp` compares
  per-layer captures. One ULP of difference sets a differing bit, so the gate
  can only ever answer "bit-exact or not".
- Measured: STATE5 reported 121 differing tensors **with** the G1 gate and 121
  **without** it (`tmp/q4e-sprint-r1-20261014/mtp-align-g1.log`,
  `mtp-align-control.log`). That is the correct read of the gate: G1 is neutral
  to it. It is not a statement about token quality, and it cannot be improved by
  narrowing tolerance - it has no tolerance.
- The released bar is Top-1 token agreement >= 95%, so the bit-exact instrument
  is strictly more expensive (extra GPU arm, full-precision dumps) and measures
  the wrong thing.

## 3. Cheapest implementation path (chosen): zero-code python comparator

`tmp/q4e-sprint-r1-20261014/mtp-top1/compare_top1.py` parses the `[MTP TARGET]`,
`[MTP LIVE]`, `[MTP VERIFY]`, `[MTP PASS]`, `[MTP CYCLES]` JSON lines the probe
already emits and prints A, B and C. No C++ change, no second probe mode, no
rebuild.

Why not C++: the probe already prints the reference stream (`[MTP TARGET]
tokens`), the committed stream (`[MTP LIVE] generated`, plus the in-probe
`single_row_target_mismatches` cross-check) and the teacher-forced argmax array
(`[MTP VERIFY] top1`). A C++ change would add a mode that recomputes data that is
already on stdout, at the cost of a rebuild that the GPU-holding sprint cannot
spend.

Validation of the comparator itself: `width 1 -> rate_B = 1.0000` in both old
logs that contain width 1 (`smoke.log` 15/15, `s4-small-rows-20260930.log`
23/23), and its section-A mismatch list reproduces the probe's own
`single_row_target_mismatches` exactly (`cross-check: True`) on the current log.

Judgement (in this order):

1. `rate_B(1) = 1.0000` in both logs. Otherwise stop: the comparison or the run
   is broken, not the model.
2. `rate_B(2) >= 0.95` in both logs -> gate passed at width 2 (production
   width). Between 0.90 and 0.95 -> report as marginal, do not flip defaults.
   Below 0.90 -> the batched path needs the alignment set
   (`VERIFY_SMALL_ROWS` / `VERIFY_DECODE_*` / `VERIFY_GDN_ORDER`) before any
   default flip; that set was measured at 6.28 tok/s, so it is a quality-only
   fallback.
3. Report `rate_A` (width 2) with `first_divergence` as the end-to-end band and
   `p1/q2` as the speed input. Do not gate on A.

Time `[est]` from measured components in the current log (per arm: load ~1 min,
prefill 30-45 s at 512/1833 tokens, T1 reference 128 x ~0.21 s ~= 27 s, four
verify passes ~= 4 x (prefill + 16-32 blocks x 0.65 s), cycle/draft passes
~= 25 s, live width-2 ~= prefill + 21 s): **~5 min for 512, ~8-10 min for
1833, i.e. ~15 min for the pair**, plus the two 15 s drains. Cheaper variant if
time is short: `AILA_Q4E_MTP_ANCHORS=60` (halves the verify positions and the T1
reference; ~2-3 min saved per arm, weaker statistics).

## 6. What this metric proves, and what it does not

Proves:

- Per step, with the same prefix, the batched verify forward (width 2, the
  production window) returns the T1 argmax token in >= 95% of positions. That is
  exactly the released gate, and it is the quantity that survives chaos.
- Because the production window commits target argmaxes only, the emitted text
  is the T1 greedy text up to that flip rate; no draft bias can enter the
  output (a wrong draft is rejected and replaced by the target argmax).

Does not prove:

- Not bit-exactness and not distributional equivalence: teacher-forced Top-1
  truncates the distribution at rank 1 and ignores logit distance, rank-2
  swaps, and any non-greedy sampling path. Do not quote this as a quality or
  perplexity result.
- Not a bound on text-level agreement: after the first flip, chaos makes the
  two texts differ everywhere (measured: 11 matching positions then
  0.0192 post-divergence). If a user needs long identical outputs, only the
  alignment set (bit-exact, slow) provides that.
- Not statistically tight at n = 63: 61/63 has a one-sided 95% lower bound of
  0.9085 (Wilson). To hold a 95% claim against an observed ~3% flip rate you
  need ~280 compared positions, i.e. both arms in paragraph 5 plus one more
  prompt (~127 positions per arm). Treat 0.95 as the practical bar and add the
  third arm before publishing the number.
- Nothing about speed, acceptance or memory; those stay with G1/G4.
- Nothing about the draft's own distribution. `p1 = 0.748` acceptance does NOT
  imply Top-1 agreement: acceptance compares the draft against the *target
  argmax* under MTP's own trajectory, while `rate_B` compares the target's
  batched argmax against the target's single-row argmax under the T1
  trajectory. The two are independent numbers, and only `rate_B` is the gate.
